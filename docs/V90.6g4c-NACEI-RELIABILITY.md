# V90.6g4c — NACEI archive readiness and bounded recovery

Status: **merged and verified in production on 2026-11-21** via [PR #108](https://github.com/LordOftheIdiot5/energy/pull/108). All cited browser and Pages checks passed; the original intermittent network cause remains unproven.

## Why this change

A 2026-11-21 production GEM browser check initially timed out while waiting for the independent NACEI 2017 archive. Its second attempt passed on desktop and mobile, and the dedicated NACEI production smoke passed. This is evidence of intermittent readiness **without an established root cause**. The existing NACEI request had no deadline and required a manual off/on toggle after any error.

## Source-preserving design

- Fetch only the previously reviewed **August 2017 NACEI historical reference**; no outside or unapproved substitution and no inference of current operating status.
- Use isolated source-specific fetch with an AbortController and whole-request deadline of **10 / 12 / 16 seconds** across at most three attempts. Backoff is **250 / 750 ms** between attempts. No indefinite polling.
- Retry only network failures, request timeouts, HTTP 408/425/429 and HTTP 5xx.
- Do **not** retry ordinary HTTP 4xx, malformed JSON or any source period, identity, licence, rights or geometry validation failure. The strict original whole-document validator must pass before publication.
- Record a visible loading/retrying/ready/unavailable state, bounded request number, and non-sensitive failure reason on the map container. Do not expose external request bodies or credentials in diagnostics.
- Retry exhaustion keeps the layer visibly unavailable with **zero NACEI records**, preserving independent GEM, EIA and UK infrastructure layers. A deliberate off/on action retries after an outage, and a successfully validated document is reused during the page session.
- No changes to the global NordlData cache, published dataset or private Cloudflare R2/D1 infrastructure.

## Test plan

Node tests with the **actual pinned historical fixture** and injected fetch transport cover 503, 429, network failures, timeout/abort, a permanent 503 (3-request cap), nontransient 404, malformed JSON and source-period forgery. The last three cases must fail closed without automatic retry.

Playwright at **1440 and 390 CSS px** tests one intercepted 503 followed by the original approved NACEI source, 1,278 source gas-processing records and displayed markers, cached toggling, explicit failure state on forged source vintages, independence of the 3,921 GEM route geometries and manual recovery after three consecutive 503 responses. Existing NACEI and GEM browser/inspector suites remain required.

After merge, verify the actual Pages deployment and production visitor/map/atlas delivery/GEM/NACEI/UK/US browser checks. The earlier failed first attempt and its rerun must remain documented.

## Limits

Bounded retries improve recoverability but do not diagnose the CDN/edge issue. This does not assert that previous failures are eliminated, nor does it profile device GPU memory or fix unrelated loader behavior. Persistent failures need source-specific diagnostics before further scope expansion.
