# Nordl Energy — master development roadmap (V90.2 → V91)
Planning baseline: 19 November 2026. Product scope: energy.nordl.dev. This is the ordered implementation plan, not an assertion that proposed capabilities are live.

## Product objective
Make Nordl Energy a daily-use, source-attributed energy research terminal and data platform. A visitor should be able to understand what changed, explore the physical system, compare underlying observations, and export usable data without needing to discover several independent sources. Retain a common brand family with Stockwatch and Leivro, while giving Energy a distinct identity.
Design references supplied by the owner: dark infrastructure globe with technology layers, capacity-scaled symbols and asset cards; US power-grid dashboard with temporal map, demand rankings, generation and interchange charts; day-ahead price analysis with comparison lines, range navigator, key readings and opportunity windows. Reinterpret in Nordl's own visual language; do not copy imagery, trademarks, or unlicensed assets.

## Daily user journeys and differentiation
1. Household: choose a bidding zone, see today's actual delivery prices and upcoming low-cost windows; understand wholesale vs retail cost; use existing calculators.
2. Researcher/student: find an asset/river/country, connect source records, explore seasonal records and download cited data.
3. Analyst/trader: compare compatible market/physical observations and validated scenarios; follow source-specific freshness; link to Stockwatch.
4. Developer/business: search the catalogue, inspect a schema, download a subset, integrate with stable API when deployed.
5. Repeat visitors: useful daily change summaries, saved preferences locally first, optional alerts/watchlists only once reliable freshness and delivery are established.

## Information architecture
Overview → Markets → Atlas → Hydrology → Grid & generation → Research charts → Datasets/API. Keep existing country, weather, commodities, infrastructure/project, historical, calculator, sources and analyst routes intact and accessible through navigation and search. Desktop compact navigation with main workspace, left filters/right inspector where useful; on mobile, collapsible filters and full-width charts and map drawers. Every graph/map detail should link to source data and appropriate export. Avoid adding another lengthy static text section for each feature.

## Measurement and business model
Free tier: public research views and existing licensed dataset downloads. Candidate paid value: maintained normalization, verified entity relations, archived revisions, validated derived indicators, custom exports, high-volume managed API and B2B integrations. Recheck upstream terms before offering any commercially redistributed feed. Keep prices and commercial launch uncommitted until cost/rights/demand are known.
Define baseline and measure: return visits, meaningful map/chart interactions, download success, dataset API usage, top entry queries, coverage (registered vs observed), data freshness by provider, data completeness, connector uptime, p75 interaction/loading metrics, support enquiries. Use privacy-conscious first-party measurement only after owner approval; no new tracking enabled by this roadmap.
Priorities by user value: discovery and daily decisions → maps → charts → deeper data/model coverage → exports/paid delivery. Collect continuously throughout.

## Release process and work tracking
Use small PRs, evidence of data and browser tests, production smoke tests, report actual results and blockers, and update this document's phase status on completion. No work is complete solely because a PR is merged or a test fixture succeeds. For user-facing changes verify actual deployed site. Hold at the current release when a blocker affects existing functionality. Start with V90.3a logo and design tokens, immediately followed by V90.3b monitor; continue dependent phases only after acceptance. Independent data collection and validation may run in parallel.
